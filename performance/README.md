# 一项索引实验

在独立数据库 `course_app_v2_perf_test` 装入 1 万名学生、600 个教学班和 10 万条选课记录。在相同数据上查询指定教学班及状态，连接学生、开课、课程和教师表并排序，两种情况下都得到 167 行。测量 SQL 在事务内移除一个非约束索引，再按原定义创建。两阶段各执行一次预热及七次正式测量。

| 条件 | 七次执行时间（毫秒） | 中位数（毫秒） |
|---|---|---:|
| 无教学班/状态索引 | 10.081、9.711、9.168、10.026、9.240、9.550、9.580 | 9.580 |
| 重建该索引后 | 2.062、1.878、2.182、1.938、1.675、1.533、1.637 | 1.878 |

这是指定查询在课程 openGauss 环境中测得的计划执行时间。无索引时需要扫描更多记录；重建后计划包含 Bitmap Index Scan。这些数据用于解释本查询的优化效果。

[测量 SQL](measure.sql) 是当时上传执行的原始文件，SHA-256 为 `e82cd2e88dc3b9073740563df381c4e70c4985b775adf7e8f783febbd6d4f644`。数据和测量脚本的生成入口是 [generate_performance.py](../scripts/generate_performance.py)。在仓库根目录运行 `python3 scripts/generate_performance.py --execute --output /tmp/kexu-perf-input` 可向新的输出目录生成 SQL；生成器本身不会连接数据库。仅在管理员准备的独立测试库中使用相应的 SQL。SQL 首先校验数据库名，实际测量保留服务器默认计划选择，避免将预热、客户端响应或其他查询计入七次样本。
